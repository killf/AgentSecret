# 部署设计

构建、编排与运行时部署约定。运行时配置项见《项目结构.md》§6 配置与密钥；迁移与启动时序细节见《后端设计/README.md》§2。

## 1. 构建与运行

常用命令由 Makefile 统一入口，内部仍由 cargo / npm 实现：

| 命令 | 作用 |
| --- | --- |
| make build | 构建单二进制 `agentsecret-server`（/api/v1、/v1 网关与 /mcp）到 server/target/release |
| make run | 本地运行（HTTP API 与 MCP 同进程） |
| make test | 单元测试 |
| make test-integration | 集成测试 |
| make lint | cargo fmt --check && cargo clippy -- -D warnings |
| make sqlx-prepare | 生成离线查询缓存（CI 用） |
| make migrate / make migrate-revert | 本地调试与应急迁移；日常由 server 启动时自动迁移（详见《后端设计/README.md》） |
| make seed-admin | 创建初始管理员账号 |
| make frontend-build | 构建前端静态资源到 `web/dist`，由 rust-embed 嵌入二进制 |

开发期依赖 `sqlx` 的编译期查询校验需要 `DATABASE_URL`；CI 用 `sqlx prepare` 生成的 `.sqlx` 离线数据，避免依赖在线库。

## 2. 部署结构

```
deploy/
├── docker-compose.yml               # server + mysql 编排
├── docker/
│   └── Dockerfile.server            # API + MCP + 静态前端（单镜像）
└── sql/init.sql                     # 数据库与最小权限角色
```

- 沙盒容器由可信执行端通过 Docker API 按任务创建；只允许白名单镜像，不挂载宿主机目录或 Docker socket。任务结束即销毁容器。
- 数据库账号按读写分离：server 用读写角色（启动迁移还需要 DDL 权限），日志查询可用只读副本。
- JWT 密钥、主密钥及服务凭据只提供给服务进程。执行凭据由部署侧显式登记并设置在可信执行端的进程环境中，按绑定在运行时读取。创建脚本容器时显式构造环境，不继承服务配置或执行凭据；不得在镜像中内置密钥。
- 镜像构建：多阶段 Dockerfile，构建阶段装 cargo-chef 缓存依赖，运行阶段用 distroless。
- 前端打包：`web/` 构建产物经 rust-embed 嵌入 `agentsecret-server` 可执行程序，部署时只有一个二进制对外提供页面与全部接口，不单独部署前端、无需静态资源服务器。
- 当前只支持单实例部署（单容器：HTTP API 与 MCP 同进程，MCP 挂载在 /mcp 路径）：数据库迁移在进程启动时自动执行，不引入独立迁移 Job（详见《后端设计/README.md》）。
- 当前可信执行端在 server 进程中，通过 Docker socket 管理沙盒。每个容器只可访问该次执行专属的内部通道；通道不做鉴权，不开放共享或公开端口，执行结束即关闭。沙盒不能直连 MySQL、模型网关或外网。上游请求由执行端按操作配置访问固定目的地。
- 沙盒容器使用 [`none` 日志驱动](https://docs.docker.com/engine/logging/configure/#supported-logging-drivers)，禁止 Docker 持久化原始输出。启动前连接输出流，分开、有界捕获 stdout/stderr，过滤后才允许写入执行记录和返回给 Agent。

## 3. 健康检查与生命周期

- compose healthcheck 的 `start_period` 为迁移期留足启动窗口，避免探针在迁移中途把进程判为失败（详见《后端设计/README.md》§2.4）。
- 迁移失败或 schema 版本不匹配时进程退出，不带病提供服务。
- 进程收到 SIGTERM 时停止接收新请求和沙盒任务，通知执行端终止并清理本服务的容器。启动后先核对遗留容器与执行记录，再接受新的沙盒任务；清理失败的容器仍占并发名额，后台重试。
