# 部署设计

构建、编排与运行时部署约定。运行时配置项见《项目结构.md》。

## 1. 构建与运行

| 命令 | 作用 |
| --- | --- |
| make build | 构建前端并编译 release 二进制 `agentsecret-server` |
| make run | 本地运行 HTTP API、模型网关与 MCP |
| make test | 后端单元测试 + 前端测试 |
| make test-integration | 连接 `AGENTSECRET_TEST_DATABASE_URL`，并使用 `TEST_RELEASE_CREDENTIAL` 假密钥执行集成测试 |
| make lint | Rust fmt/clippy + 前端 TypeScript 检查 |

- 后端启动时执行唯一的 `0001_init.sql`，成功后才监听端口。
- 前端在 Docker 构建内由 Node 阶段构建，并由 RustEmbed 嵌入后端二进制。
- 沙盒容器使用白名单镜像，不挂载宿主机目录或 Docker socket；执行结束即销毁。

## 2. 部署结构

```text
deploy/
├── docker-compose.yml
├── docker/
│   └── Dockerfile.server
└── sql/
    └── init.sql
```

- `Dockerfile.server` 包含前端构建、后端 release 构建和 distroless 运行阶段。
- `docker-compose.yml` 启动 MySQL 与 server；server 通过只读 Docker socket 创建沙盒。
- Linux 部署需提供宿主机 `DOCKER_GID`，让非 root server 进程获得 Docker socket 组权限。
- 数据库账号权限由 `deploy/sql/init.sql` 与 MySQL 环境变量共同约束。
- JWT 密钥、主密钥和数据库密码只注入服务进程，不写入镜像或仓库。`AGENTSECRET_CREDENTIAL_ACTIONS` 注入动作目录，动作引用的密钥仍由部署侧以独立环境变量注入服务进程。

## 3. 健康检查与生命周期

- `/health` 用于进程与编排健康检查。
- MySQL healthcheck 的 `start_period` 覆盖初始化窗口。
- 迁移失败时进程退出，不监听 HTTP。
- server 收到 SIGTERM 后停止接收新请求；执行中的沙盒任务完成输出过滤和容器清理后退出。
