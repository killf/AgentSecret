# 项目结构

## 1. 仓库总览

单仓库（monorepo）：后端为单 crate Rust 工程（二进制 `agentsecret-server`，同一进程提供 /api/v1 管理接口、/v1 模型网关与 /mcp），前端独立工程，共享一份 API 契约；数据库为 MySQL 8.0。

```
AgentSecret/
├── Makefile                  # 前后端构建 / 测试 / 检查统一入口
├── web/                      # 前端工程（React + TS + Vite），构建产物 rust-embed 嵌入
├── server/                   # 后端单 crate 工程（二进制 agentsecret-server）
│   ├── Cargo.toml            # 单 crate 清单（package + dependencies）
│   ├── rust-toolchain.toml   # 固定工具链版本（stable，MSRV 1.100）
│   ├── rustfmt.toml
│   ├── clippy.toml
│   ├── migrations/           # sqlx 迁移脚本
│   └── src/
├── deploy/                   # 部署清单（docker/、sql/）
└── docs/                     # 设计文档
```

## 3. 模块分层与依赖方向

依赖单向向下，禁止反向与循环：

```
main / router ──→ service ──→ model（领域模型 + Repository / UpstreamClient / SandboxRunner trait）
      │
      └──启动时注入──→ store（sqlx 实现 Repository）
```

- `model`：领域模型（对应数据库表）、`AppError` 与错误码、trait 定义（`Repository`、`UpstreamClient`、`SandboxRunner`、`SecretStore`）、配置结构体、AES-GCM 加解密、加盐口令处理（每用户随机盐 + SHA-1）、敏感信息规则引擎。不依赖 web 框架与 sqlx。
- `store`：sqlx 实现 `Repository`，按表分文件（`user.rs`、`provider.rs`、`model.rs`、`access_log.rs`…）。只做 CRUD 与聚合查询，不含业务判断；迁移逻辑也在这里，由 `main` 启动时调用。
- `service`：业务逻辑（登录、令牌、配额、权限判定、网关路由、沙盒调度）。事务边界在这一层；返回 `AppError`。
- `handler` / `middleware` / `extractor` / `dto`：actix-web 路由装配与中间件、提取器（`AuthUser` / `AdminUser`）、请求/响应结构；同进程挂三个路由面：`/api/v1` 管理接口、`/v1` 模型网关（Responses 格式）、`/mcp`（协议层用 `rmcp`，工具复用 `service`）。

> `service` 通过 `model` 中的 trait 访问数据，`store` 在启动时注入（依赖注入），避免 service 直接依赖 sqlx 类型，便于测试时替换内存实现。

## 4. server/src 内部模块示例

```
server/src/
├── main.rs             # 启动：配置加载、迁移、依赖注入、HTTP 服务
├── args.rs             # clap 启动参数（--database-url）
├── config.rs           # Config 结构体 + 环境变量加载与校验

├── state.rs            # AppState（db pool、service、config、http client）→ web::Data
├── router.rs           # /api/v1 + /v1 + /mcp 路由装配
├── model/              # 领域模型与 trait
│   ├── user.rs
│   ├── token.rs
│   ├── provider.rs
│   ├── model.rs        # 模型、模型-供应商关系
│   ├── log.rs
│   ├── project.rs      # 项目、环境、变量
│   ├── script.rs       # 脚本、执行记录
│   └── sandbox.rs
├── store/              # sqlx 实现 Repository，按表分文件
├── service/            # 业务逻辑，事务边界在这一层

│   ├── permission/     # 项目/环境/模型/供应商权限判定

│   ├── gateway/        # 网关主链路：router.rs + upstream/（minimax / glm / codex）+ usage.rs
│   ├── sandbox/        # 一次性容器、运行时凭据操作、执行结果过滤
│   └── admin/          # 用户、供应商、模型、权限管理

├── sensitive/          # 敏感信息规则引擎

│   ├── matcher.rs
│   └── scanner.rs

    ├── mod.rs          # rmcp Server 组装，挂载到 /mcp 路径

        ├── project_list.rs
        ├── script_list.rs
        ├── script_run.rs
        └── execution_status.rs
```

## 5. 前端结构

```
web/
├── src/
│   ├── api/            # 接口封装，一个模块一个文件
│   │   ├── client.ts   # fetch 封装、token 注入、错误处理
│   │   ├── auth.ts
│   │   ├── tokens.ts
│   │   ├── logs.ts
│   │   ├── models.ts
│   │   ├── providers.ts
│   │   ├── projects.ts # 项目、环境、变量、脚本
│   │   ├── users.ts
│   │   └── permissions.ts
│   ├── components/     # 通用组件（权限选择器、状态标签、刷新开关、敏感信息提示）
│   ├── pages/          # 页面组件，与路由一一对应
│   ├── stores/         # 登录态等全局状态
│   ├── hooks/          # 自定义 hooks（分页、自动刷新、SHA-1）
│   ├── utils/          # sha1、时间格式化、脱敏展示
│   ├── types/          # 与后端 DTO 对齐的 TypeScript 类型
│   ├── router.tsx
│   └── main.tsx
├── public/
├── package.json
└── vite.config.ts
```

约定：

- 页面组件不直接调用 `fetch`，一律走 `src/api/`。
- 后端 DTO 变更后同步更新 `src/types/`，类型手工维护、与《后端设计/后端接口.md》的请求/响应表保持一致。
- 自动刷新逻辑抽成 `useAutoRefresh(interval)` hook，页面只传间隔。
- 前端构建产物（`web/dist`）由 `rust-embed` 编译期嵌入 server 二进制，随单二进制部署；本地开发用 Vite dev server 将 `/api` 代理到后端。

## 6. 配置与密钥

| 变量 | 用途 | 是否必填 |
| --- | --- | --- |
| DATABASE_URL | MySQL 连接串（`mysql://user:pass@host:3306/db`），可由环境变量或启动参数 `--database-url` 提供 | 必填 |
| AGENTSECRET_JWT_SECRET | 登录 Token 签名密钥 | 必填 |
| AGENTSECRET_MASTER_KEY | 供应商令牌加密主密钥（AES-256） | 必填 |
| AGENTSECRET_ADDR | HTTP 监听地址，默认 0.0.0.0:8080 | 否 |
| AGENTSECRET_DOCKER_HOST | 沙盒使用的 Docker API 地址，默认 `unix:///var/run/docker.sock` | 否 |
| AGENTSECRET_SANDBOX_NETWORK | 沙盒容器所在 Docker 网络名，默认 agentsecret-sandbox | 否 |
| AGENTSECRET_TOKEN_TTL_DAYS | 登录 Token 有效期，默认 7 | 否 |
| AGENTSECRET_LOG | 日志格式：pretty / json，默认 json | 否 |

执行凭据由部署侧登记，可信执行端按项目和环境下的绑定在运行时读取对应环境变量；这些值不进入沙盒或常规配置日志。

配置由 `core::config::Config::from_env()` 统一加载，启动时校验必填项；密钥不落仓库、不进日志（打印配置时掩码）。
启动参数由 server 用 clap 解析，当前只覆盖连接串一项（`--database-url`）：命令行参数优先于环境变量，其余配置仍只来自环境变量。

`DATABASE_URL` 对应的账号需要 DDL 权限（CREATE/ALTER/INDEX 等），因为迁移在服务启动时自动执行；建库与建角色由 `deploy/sql/init.sql` 预先完成。

## 8. 测试约定

| 位置 | 方式 |
| --- | --- |
| server/src/**_test.rs | 单元测试，`#[cfg(test)]` |
| server/tests/ | 集成测试，`#[cfg(feature = "integration")]` |
| 上游模拟 | wiremock / httpmock 起假服务 |
| 数据库 | sqlx 连接真实 TEST 库，或用 testcontainers 起临时 MySQL 8.0 |
| 沙盒 | 单元测试用 mock runner；集成验收用隔离测试容器和假凭据，验证实际隔离、过滤和销毁 |

- 单元测试不依赖外部服务；集成测试用 feature 隔离。
- 关键业务路径（登录封禁、配额判定、供应商路由、敏感规则匹配）必须有单元测试覆盖。
