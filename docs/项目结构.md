# 项目结构

## 1. 仓库总览

单仓库：后端为单 crate Rust 工程，二进制 `agentsecret-server` 同进程提供 `/api/v1` 管理接口、`/v1` 模型网关与 `/mcp`；前端独立工程；数据库为 MySQL 8.0。

```text
AgentSecret/
├── Makefile                  # 前后端构建 / 测试 / 检查统一入口
├── web/                      # 前端工程（React + TS + Vite），产物由后端嵌入
├── server/                   # 后端单 crate 工程
│   ├── Cargo.toml
│   ├── rust-toolchain.toml
│   ├── rustfmt.toml
│   ├── migrations/
│   │   └── 0001_init.sql    # 第一版唯一初始化迁移
│   └── src/
│       ├── main.rs           # 启动：配置、迁移、数据库连接、路由、HTTP 服务
│       ├── config.rs         # 环境变量配置加载与校验
│       ├── error.rs          # 业务错误码与 HTTP 响应映射
│       ├── state.rs          # AppState：数据库连接、配置、令牌工具
│       ├── router.rs         # /api/v1、/v1、/mcp 路由装配
│       ├── controller/       # 控制器：请求/响应编排、权限判断、编号注释
│       ├── schema/           # HTTP 请求与响应结构
│       ├── entity/           # SeaORM 实体、表关系与实体级查询方法
│       ├── service/          # 认证、令牌、网关、沙盒等跨实体业务服务
│       ├── middleware/       # 登录鉴权、管理员鉴权、访问令牌鉴权、请求 ID
│       └── utils/            # 加密、JWT、脱敏、时间等无状态工具
├── deploy/                   # Docker Compose、Dockerfile、数据库初始化角色
└── docs/                     # 设计文档
```

## 2. 后端依赖与分层

后端使用 Actix Web + SeaORM：

```toml
[dependencies]
actix-web = "4"
sea-orm = { version = "2.0", features = ["sqlx-mysql", "runtime-tokio-rustls", "macros"] }
```

依赖方向保持单向：

```text
router → controller → service → entity
                       └→ schema
```

- `schema`：只描述 HTTP 请求与响应，不包含数据库访问逻辑。
- `entity`：一表一文件，使用 `DeriveEntityModel` 定义模型、列、关系和 `ActiveModel`；实体文件内可提供复用查询方法。
- `controller`：解析请求、调用实体或服务、组装响应；复杂流程用短中文编号注释说明步骤。
- `service`：只保留跨实体或跨协议的业务能力，例如登录会话、访问令牌、模型路由、沙盒调度；不做薄转发。
- 不设置 `store` / repository 层，控制器和服务直接通过 SeaORM `DatabaseConnection` 访问实体。

## 3. 配置与密钥

| 变量 | 用途 | 是否必填 |
| --- | --- | --- |
| DATABASE_URL | MySQL 连接串 | 必填 |
| AGENTSECRET_JWT_SECRET | 登录与访问令牌签名密钥 | 必填 |
| AGENTSECRET_MASTER_KEY | 供应商令牌 AES-256-GCM 主密钥，32 字节 | 必填 |
| AGENTSECRET_ADDR | HTTP 监听地址，默认 `0.0.0.0:8080` | 否 |
| AGENTSECRET_CREDENTIAL_ACTIONS | 预定义凭据动作目录 JSON；空值表示未登记动作 | 否 |
| AGENTSECRET_PROVIDER_QUOTAS | 供应商类型到额度接口的映射 JSON；空值表示未启用刷新 | 否 |
| AGENTSECRET_TOKEN_TTL_DAYS | 登录会话有效期，默认 7 天 | 否 |
| AGENTSECRET_LOG | `json` / `pretty` | 否 |

命令行 `--database-url` 优先于环境变量。密钥不写入仓库、不输出到日志。

`AGENTSECRET_CREDENTIAL_ACTIONS` 以动作 ID 为键，每个动作固定 `method`、`url`、`credential_key`、`credential`、`parameters` 与 `response_fields`。脚本审核时会保存动作目录指纹；目录变化后旧批准不能执行。

`AGENTSECRET_PROVIDER_QUOTAS` 以供应商类型为键，映射固定 `path`、`field_5h`、`field_weekly` 与可选 `field_monthly`；服务端用供应商令牌请求 `base_url + path` 并回写统一额度字段。

## 4. 数据库迁移

- 第一版只保留一个迁移：`server/migrations/0001_init.sql`。
- 启动时自动执行初始化迁移，成功后才监听 HTTP。
- 迁移只负责创建第一版完整 schema；后续版本再追加新迁移，不修改已发布迁移。
- 本地集成测试使用 Docker 启动隔离 MySQL 8.0，测试后删除容器和卷。

## 5. 前端结构

前端使用 React + TypeScript + Vite：

```text
web/
├── src/
│   ├── api/           # fetch 封装与后端接口模块
│   ├── components/    # 通用组件
│   ├── pages/         # 页面组件
│   ├── stores/        # 登录态等全局状态
│   ├── hooks/         # 自动刷新、分页等 hook
│   ├── utils/         # SHA-1、时间、脱敏工具
│   ├── types/         # 与 schema 对齐的类型
│   ├── router.tsx
│   └── main.tsx
├── package.json
└── vite.config.ts
```

页面不直接调用 `fetch`，统一走 `src/api/`；构建产物 `web/dist` 嵌入后端二进制，本地开发用 Vite 代理 `/api`、`/v1` 和 `/mcp`。

## 6. 测试约定

| 范围 | 方式 |
| --- | --- |
| 单元测试 | `cargo test`，不依赖外部服务 |
| API 集成测试 | Actix test service + Docker MySQL 8.0 |
| 迁移测试 | 空 MySQL 执行唯一 init 迁移并启动服务 |
| 前端测试 | Vitest 组件与 API mock 测试 |
| 网关测试 | 上游模拟服务验证路由、鉴权、配额、日志 |
| MCP 测试 | MCP 客户端模拟访问令牌、工具调用与错误语义 |
| 沙盒测试 | 隔离容器、假凭据、实际创建/销毁与输出过滤 |

所有功能完成后必须通过 `make lint`、后端测试、前端测试、迁移集成测试和端到端关键路径测试。
