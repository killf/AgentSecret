# MCP 工具设计

## 1. 定位

通过 MCP 协议把 AgentSecret 的核心工作流暴露给 AI Agent：查看可访问的项目与脚本、在受控沙盒执行脚本、查询执行进度（受权限与敏感信息过滤约束）。

MCP 与 HTTP 接口的关系：

1. **同进程部署**：MCP 以 `/mcp` 路径挂载在 `agentsecret-server` 上，与 HTTP API 共用端口、连接池、配置与后台任务，不单独起服务。
2. **复用 service 层**：配额校验、供应商路由、敏感信息过滤、日志落库走同一套实现，不做旁路。
3. **鉴权不同**：HTTP 接口用登录会话（`b_users.session_token`），MCP 用访问令牌（`b_access_tokens`）；鉴权链路分开实现，进入 service 层后统一。
4. **凭据边界**：工具、资源和错误响应均不读取或返回密钥明文。脚本执行需要认证时，由可信执行端在运行时从自己的环境变量取值并代为使用，脚本进程不继承这些变量。
5. **可审计**：工具调用在操作日志记录调用者、动作、对象和结果；脚本执行另外保存执行记录。审计只记录标识和固定原因码，不记录密钥、原始输出或上游原始错误。

## 2. 技术选型

- 协议实现：官方 Rust SDK（`rmcp`，modelcontextprotocol/rust-sdk），以 actix-web 路由形式挂载在 `agentsecret-server` 的 `/mcp` 路径。
- 传输：仅 Streamable HTTP，不支持 stdio。
- 配置、加密与 HTTP 客户端复用 `model` 模块，业务复用 `service` 模块；语言与运行时遵循后端统一选型（见 README）。
- 若 SDK 某版本能力不足，可退化为在 actix-web 上手写 JSON-RPC（协议面很小）。

## 3. 传输与鉴权

- 传输：Streamable HTTP，端点 `POST /mcp`。
- 鉴权头：`Authorization: Bearer <access_token>`（`b_access_tokens` 表令牌，不使用登录会话）。
- 鉴权流程：JWT 验签 → 按 `token` 查库确认未禁用、未过期 → 载入用户与权限（模型/供应商/项目/环境）。
- 实现：MCP 专用鉴权中间件（与 HTTP API 的会话 `auth` 中间件分开，令牌来源不同），通过后把身份写入请求扩展；service 层无感知差异。
- 传输层同时支持 `MCP-Protocol-Version` 头与 `Mcp-Session-Id` 协商；服务端保持无状态（每次请求携带令牌）。

## 4. 工具清单

### 4.1 project_list — 项目列表

请求：无。

响应：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| projects | ProjectInfo[] | 当前用户可访问的项目列表 |

自定义类型 `ProjectInfo`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 名称 |
| description | string? | 描述 |
| guidance | string? | 项目指导 |
| repos | string[] | 仓库地址数组 |

行为：仅返回当前用户可访问且未禁用的项目。

### 4.2 script_list — 脚本列表

请求：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project | string | 是 | 项目名 |

响应：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| scripts | ScriptInfo[] | 该项目下的脚本列表 |

自定义类型 `ScriptInfo`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 名称 |
| type | string | bash / python |
| description | string? | 描述 |
| environment_name | string? | 绑定环境名 |
| sandbox_name | string? | 指定沙盒名 |
| updated_at | datetime | 更新时间 |

行为：校验项目权限和脚本绑定的环境权限，只返回审核通过的脚本；不返回代码、凭据绑定或环境变量名。项目名全局唯一，环境名项目内唯一，脚本名在项目及绑定环境范围内唯一。

### 4.3 script_run — 执行已审核脚本

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project | string | 是 | 项目名 |
| environment | string? | 否 | 脚本已审核的绑定环境；不绑定环境的脚本省略此项 |
| script_name | string | 是 | 已审核的脚本名 |
| params | object | 否 | 按审核通过的参数定义传值，参数只作为数据使用 |

服务端校验账号、项目、绑定环境和版本的审核状态。MCP 不接受内联代码、环境覆盖、命令、凭据名称或凭据值。无环境脚本不能申请凭据操作。

响应使用下节的执行结果。默认等待最多 5 秒；超出等待窗口返回执行 ID 和当前状态，由 Agent 调用 `execution_status`。等待窗口结束或 MCP 连接断开，不等于执行结束。

### 4.4 execution_status — 查询执行进度

参数：`execution_id`（bigint，必填）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| execution_id | bigint | 执行 ID |
| status | string | pending / running / success / failed / timeout / canceled |
| started_at | datetime? | 开始时间 |
| finished_at | datetime? | 结束时间 |
| duration_ms | int? | 耗时 |
| stdout | string? | 终态才返回，且必须完成过滤 |
| stderr | string? | 终态才返回，且必须完成过滤 |
| error_code | string? | 服务端定义的固定原因码 |

查询使用执行记录中保存的项目和环境。普通用户还必须是该次执行的发起人；管理员可以审计。同步返回、轮询、Web 执行日志和 MCP Resource 共用已经过滤的结果。

## 5. 沙盒执行

### 5.1 脚本编辑与审核

仅管理员通过 Web 管理接口新增、编辑、审核和删除脚本，MCP 令牌没有这些操作。另一位管理员审核指定版本，核对脚本实现、参数、绑定环境、沙盒和允许的凭据操作。参数不能变成代码、Shell 片段或凭据操作目的地。删除脚本沿用执行历史的引用限制。

任何编辑都递增版本并回到待审核；审核请求必须携带版本，版本不符或审核人是该版本最后编辑者时拒绝。审核通过后只允许执行该版本。凭据绑定变化时，受影响脚本的版本递增并重新审核。审核、驳回及编辑操作记录操作者、脚本 ID、版本和结果。

### 5.2 运行时使用密钥

1. 网页和 MCP 共用同一执行服务。提交时固定已审核的脚本和参数；启动前重新核对账号、项目、环境、版本和所需凭据绑定。未通过时不启动容器。
2. 已审核脚本只可调用事先定义的凭据操作。环境变量只挂在项目和环境下。预定义操作从脚本已绑定的环境取所需变量，并访问固定上游目标。脚本只能传经过校验的业务参数，不能传任意 URL、请求头、命令或环境变量名。操作的目的地策略一旦变更，须重新审核后才能执行。
3. 可信执行端使用当前执行已确定的项目和环境解析变量别名，运行时读取自己的进程环境并完成上游认证。密钥不放入脚本环境、命令行、文件、参数、容器配置或响应。操作仅提取并校验作业状态、数量等事先允许的业务字段，向脚本返回前也检查是否含本次密钥；不透传上游原始响应、响应头和错误。所需凭据缺失或绑定变更时拒绝，不能回退到其他环境或凭据。
4. 每次执行使用只有本次容器能访问的内部通道。通道不做鉴权，不签发令牌；执行端在创建通道时固定执行上下文，不从请求接收项目、环境或执行 ID。执行结束即关闭通道。脚本容器不能直连业务数据库、模型网关或外部网络。

例如，Agent 执行已审核的「查询发布状态」脚本，只传发布单号。脚本调用已批准的查询操作；可信执行端读取该环境绑定的凭据，从固定发布系统获取状态。脚本拿到状态并写入 stdout；Agent 获得执行 ID 和过滤后的输出。

### 5.3 一次性容器

1. 执行通过准入后创建执行记录和本次专属的沙盒实例记录。在同一事务内锁定沙盒配置行、检查最大并发数并创建两条记录；满载则返回超限，不入队，也不创建执行记录。实例从创建到确认销毁都占并发名额。
2. 每次执行创建新容器，只运行这一条任务。使用白名单镜像和受限配置：非 root、只读根文件系统、无特权、丢弃 capabilities、限制 CPU 和内存、不挂载宿主机目录或 Docker socket。容器标记所属服务和执行 ID。
3. 执行成功、失败、取消或超时均停止并销毁容器；保留数据库中的执行记录与实例状态用于审计。清理失败时标记待重试，继续占并发名额；服务重启时仅清理带本服务标记的遗留容器，把中断任务标为失败，不自动重放脚本。

### 5.4 输出过滤

stdout、stderr 分别在执行结束时对完整、有界的输出进行过滤。执行端只在服务内存保留本次用到的密钥用于过滤，按已知明文和明确支持的常见编码匹配，并应用通用敏感规则；不能逐块发给 Agent。执行操作自身的日志和错误也不得含密钥。禁用容器原始日志持久化；服务端在过滤前不转发、不落库、不打印原始输出。

输出超限、捕获中断、编码无法识别、过滤器报错等不能安全确认的情况，丢弃对应输出，只返回固定说明。执行记录只保存过滤后的内容。过滤是附加防线；主要保护来自脚本无法取得密钥明文、凭据操作限定目的地及响应字段。

### 5.5 验收场景

- 普通用户能执行授权范围内已审核的脚本，不能编辑或审核；管理员不能审核自己编辑的版本。编辑后旧审核失效，执行入口不能以环境覆盖或内联代码绕过。
- 用假密钥验证：脚本无法从环境、参数或文件读到密钥，凭据操作能替它完成认证；上游回显或输出跨块出现假密钥时，MCP 同步返回、轮询、Resource、Web 日志和持久化日志都无明文。过滤失败只返回固定说明。
- 用不同项目和环境中的同名变量验证各自取值；并行启动两个测试容器，确认它们各自可以无令牌调用自己的通道，访问不了对方的通道。
- 用隔离的测试容器顺序运行两次，实例标识各不相同；成功、失败和超时后均无残留容器。模拟一次清理失败和服务恢复，确认无重复执行且未清理实例仍占并发名额。

## 6. 资源（Resources）

以只读资源形式暴露，便于客户端浏览：

| URI | 内容 |
| --- | --- |
| agentsecret://projects/{project_id}/environments | 某项目下可见环境 |
| agentsecret://executions/{execution_id} | 执行记录详情 |

环境资源按项目及环境权限裁剪，且不返回凭据绑定；执行资源与 `execution_status` 使用同一授权和已过滤结果。

## 7. 权限矩阵

| 工具 | 项目权限 | 环境权限 | 额外条件 |
| --- | --- | --- | --- |
| project_list | 仅返回可见项目 | — | — |
| script_list | 需要 | 已绑定时需要 | 仅返回已审核版本 |
| script_run | 需要 | 已绑定时需要 | 仅执行指定的已审核版本 |
| execution_status | 需要 | 以执行记录为准 | 普通用户仅查询本人执行 |

管理员可跳过项目和环境授权，但仍须检查资源禁用状态与版本审核状态。执行时长和次数受配额限制。

## 8. 错误语义

MCP 工具错误用 `isError: true` + 结构化内容返回，不用协议级错误，
便于 Agent 自行恢复。错误码与 `/api/v1` 业务码同一体系
（1 参数错误、2 未认证、3 无权限、4 不存在、5 超限、
6 上游失败、7 服务端错误）：

```json
{ "error": { "code": "3", "message": "无该模型权限", "retryable": false } }
```

`retryable` 标记：5（用户配额超限）、6（上游失败，重试一次后仍失败）
为 true；1 / 2 / 3 / 4 / 7 为 false。实现上把 `AppError`
映射为该结构，工具返回类型统一为 `Result<CallToolResult, McpError>`。

## 9. 调用限制

- 单连接并发：默认 4 个在途工具调用，超出排队（tokio `Semaphore`）。
- 每令牌速率限制：列表与查询类工具 30 次/分钟，执行脚本 10 次/分钟。
- 沙盒执行默认超时 600 秒，超时终止并销毁容器，执行记录标记 timeout。
