# 后端接口设计

路径均以 `/api/v1/` 开头，全部使用 `POST`：不使用路径参数与 query，资源定位与过滤参数一律放请求体。动作后缀约定：列表 `/list`、详情 `/detail`、新增 `/add`、更新 `/update`、删除 `/delete`。路径中的 `v1` 仅是 API 版本号，未来不兼容升级时发布 `/api/v2/` 并行，旧版本按弃用策略下线。响应体 `{ code, message, data }`。只要服务正常返回，HTTP 状态码一律为 `200`，结果由响应体 `code` 表达：`0` 成功，非 0 表示失败。错误码：`1` 参数错误、`2` 未认证/令牌无效、`3` 无权限、`4` 不存在、`5` 超限、`6` 上游失败、`7` 服务端错误。该业务码是全系统唯一错误码体系，网关 /v1 与 MCP 的映射见各自文档。

## 1. 认证与鉴权

### 1.1 密码存储与校验

- 前端传输：`sha1(密码)` 一次，**不加盐**。
- 后端存储：每用户随机 16 字节盐（hex 32 字符），入库值为 `sha1(salt + 前端 SHA-1 值)`，`CHAR(40)`。
- 校验时按用户盐重算比对；修改密码时重生成盐，历史密文全部失效。

### 1.2 登录

1. 按 email 查用户，比对 `sha1(salt + 提交的 password)` 与库中 `password`。
2. 失败计数：查 `b_user_operation_logs` 中该用户 `type=login` 且 `status=failed` 的近 5 分钟记录；累计 5 次 → 写 `banned_at` / `unban_at`（+30 分钟），返回「已封禁」。本次失败同时写一条 `b_user_operation_logs`（type=login、status=failed、description=失败原因）。
3. 成功：签发 JWT（`sub`=user_id、`role`、过期默认 7 天），写入 `b_users.session_token` 与 `session_expire_at`，写 `b_user_operation_logs`（type=login、status=success）。

### 1.3 JWT 校验链（每个受保护请求）

实现为 actix-web 中间件 `Auth`（`middleware::from_fn`）：

1. 取 `Authorization: Bearer <token>`（用 actix-web-httpauth 的 `BearerAuth` 提取）。
2. 验签 + 校验 exp（密钥来自 `AGENTSECRET_JWT_SECRET`）。
3. 解析出 user_id → 查库确认用户存在、未处于禁用期。
4. 校验 `b_users.session_token` 与请求 token 一致（退出登录后 token 立即失效）。
5. 把 `AuthUser` 写入请求扩展（`req.extensions_mut().insert(user)`）。

处理器通过实现 `FromRequest` 的 `AuthUser` 提取器直接拿到已认证用户，避免重复解析；提取器在 `ready()` 中完成异步查库。

访问令牌（模型网关 / MCP）不走登录会话，校验链见《模型网关.md》§1 与《MCP工具.md》§3。

中间件注册顺序（外层到内层）：

```
App::new()
  .wrap(Logger)                      // tracing-actix-web
  .wrap(from_fn(request_id))         // 生成并回写请求 ID
  .wrap(from_fn(auth))               // JWT 校验链
  .wrap(from_fn(require_admin))      // 管理员校验
  .service(web::scope("/api/v1")...)
```

### 1.4 中间件与提取器职责

| 组件 | 作用 |
| --- | --- |
| Logger | tracing-actix-web，记录方法、路径、状态、耗时 |
| request_id | 生成请求 ID，贯穿日志与上游调用头 |
| auth | JWT 校验链，写入 `AuthUser` 扩展 |
| require_admin | 校验 `AuthUser.is_admin` |
| permission | 集合级权限过滤（列表接口按权限裁剪） |
| AuthUser（提取器） | 实现 `FromRequest`，处理器直接取当前用户 |
| AdminUser（提取器） | 实现 `FromRequest`，未通过管理员校验返回业务码 3 |

资源级权限（某个项目/环境/模型是否属于当前用户）在 service 层判定。

## 2. 接口契约

以下每个接口给出：请求、响应表格与执行流程。除标注「管理员」外均要求登录；响应统一包裹在 `{ code, message, data }` 中，表格只列 `data` 内容，错误响应见开头错误码。

### 2.1 认证与自身

#### POST /api/v1/auth/login — 登录

请求：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| email | string | 是 | 登录邮箱 |
| password | string | 是 | 前端 `sha1(密码)` 值，不加盐 |

响应：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| token | string | JWT 登录令牌 |
| expires_at | datetime | 令牌过期时间（默认 7 天） |
| user.id | bigint | 用户 ID |
| user.email | string | 邮箱 |
| user.name | string | 显示名 |
| user.is_admin | bool | 是否管理员 |

执行流程：

1. 按 email 查用户；不存在按统一失败处理（不区分「用户不存在」）。
2. 用户处于封禁期（`banned_at` 非空，且 `unban_at` 为空表示永久封禁或尚未到期）→ 返回「已封禁」。
3. 比对 `sha1(salt + password)`，失败走失败计数（近 5 分钟累计 5 次写封禁），写失败审计日志。
4. 成功：签发 JWT，写 `session_token`/`session_expire_at`，写成功审计日志。

#### POST /api/v1/auth/logout — 退出登录

请求：无。

响应：无（`data: null`）。

执行流程：

1. 清空当前用户 `session_token` 与 `session_expire_at`。
2. 写 `b_user_operation_logs`（type=logout）；前端清除本地 token。

#### POST /api/v1/auth/password — 修改自己的密码

请求：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| old_password | string | 是 | 前端 SHA-1 值 |
| new_password | string | 是 | 前端 SHA-1 值 |

响应：无。

执行流程：

1. 按当前盐比对 `old_password`，错误返回 1。
2. 生成新盐，写入 `sha1(new_salt + new_password)` 与新盐。
3. 清空 `session_token` 强制重新登录；写 `b_user_operation_logs`（type=password_change）。

#### POST /api/v1/auth/me — 当前用户信息

请求：无。

响应：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 用户 ID |
| email | string | 邮箱 |
| name | string | 显示名 |
| is_admin | bool | 是否管理员 |

执行流程：

```text
user = auth_context()                    // 中间件已写入 req.extensions
return { id: user.id, email: user.email, name: user.name, is_admin: user.is_admin }
```

#### POST /api/v1/tokens/reset — 重置令牌

| 参数 | 类型 | 必填 | 说明 |

```text

t.token = new_token               // 旧令牌立即失效
t.save()
audit_log(type = "token_reset", target = :id)
return { token: new_token, expires_at: t.expires_at }
```

执行流程：

```text

         provider_id: :provider_id, status: :status,
         start: :start, end: :end }

    cond.user_id = auth.user.id          // 非管理员强制查自己

       .order_by(created_at, desc)       // 走 created_at 索引

       .with_related(user: User.email, model: Model.name,
                     provider: Provider.name)

// 不含请求/响应详情字段
```

请求：`id`（bigint，必填）。响应：`ExecutionItem`，另含 `stdout`、`stderr`（已过滤，可空）和 `error_code`（固定原因码，可空）。

与列表及 MCP 查询共用执行记录授权规则。接口不读取或返回原始输出、脚本源码、实际参数、凭据配置或运行时环境。

#### POST /api/v1/scripts/detail — 脚本详情

请求：`id`（bigint，必填）。响应：`ScriptItem` 加参数定义 `params`。参数定义为 `{name: {type, required, description}}`，`type` 仅支持 `string` / `integer` / `boolean`，运行时拒绝未定义字段和类型不匹配的值。普通用户与列表的可见范围一致；管理员另可查看源码 `content`、凭据操作配置 `credential_actions`、编辑者和审核者标识。详情不得返回实际凭据值。

#### POST /api/v1/scripts/add、/scripts/update、/scripts/delete — 管理脚本

仅管理员的 Web 登录会话可调用。新增传 `project_id`、`name`、`type`、`content`（必填），以及 `description`、`environment_id`、`sandbox_id`、`params`、`credential_actions`（可选）；返回 `{ id, revision }`。

更新传 `id`、`revision` 和待更新字段，不能变更所属项目；返回更新后的 `{ id, revision }`。删除传 `id`，存在执行记录时拒绝删除，成功时无响应数据。

新增或编辑校验环境、沙盒与凭据绑定均归属对应项目和环境。`credential_actions` 使用 `{ "version": 1, "actions": [{ "action_id": "...", "binding_id": 1 }] }`；提交端不能提供原始密钥、任意目的地或命令，服务端会在审核时写入部署侧动作目录指纹。按版本条件更新；脚本新增或编辑后进入待审核，清空上一版本的批准。

bash 脚本调用 `agentsecret_action <action_id> <params_json>`，Python 脚本调用 `agentsecret_action(action_id, params)`。该入口只通过本次容器附加流访问已审核动作；密钥保留在服务进程，容器环境不包含密钥。

#### POST /api/v1/scripts/review — 审核脚本

请求：`id`、`revision`（bigint，必填），`decision`（string，`approve` / `reject`，必填）。成功无响应数据。

仅管理员的 Web 登录会话可审核，且不能审核自己最后编辑的版本。只审核待审核的匹配版本。通过时固定凭据操作及绑定；审核及结果写入操作日志。MCP 令牌不能调用脚本编辑或审核接口。

#### POST /api/v1/scripts/run — 执行脚本

请求：`id`（bigint，必填），`params`（object，可选），不接受环境覆盖、内联代码、凭据名称或凭据值。响应：`{ execution_id }`。

调用 MCP `script_run` 使用的执行服务，按脚本绑定环境和当前审核版本准入。启动前再次核对权限和审核版本；每次执行使用独立容器。已过滤的输出通过执行详情查询。

## 3. 安全基线

- 密码加盐存储（见 §1.1）：前端 SHA-1 一次不加盐，后端每用户随机盐 + SHA-1；风险在于 SHA-1 强度有限，靠强密码策略、失败锁定与限流补偿，升级 bcrypt/argon2 时按盐字段灰度迁移。
- 供应商令牌用 AES-256-GCM 加密存储，主密钥禁止入库。脚本凭据只在可信执行端运行时从自身环境读取，管理接口只保存绑定。
- 管理接口统一 `require_admin` + 审计日志。
- 执行服务在运行结果落库与返回前统一过滤 stdout/stderr，不能安全过滤时丢弃原文。模型网关的请求、响应扫描见《模型网关.md》。
- 所有接口按用户维度限流（令牌 60 次/分钟、网关 30 次/分钟），登录接口按 IP + 邮箱限流。
- 敏感值在日志中一律掩码：tracing 的自定义字段序列化器对 `password`、`token`、`access_token`、`value` 等键做脱敏。
